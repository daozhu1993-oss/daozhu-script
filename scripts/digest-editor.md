# 编剧与漫剧日刊值班说明

在编剧工坊正式工程（daozhu-script）的最新 main 上工作。日期按上海时间。先对照源库和正式域名 /digest/ 的日期。同日已有稿时只核对发布状态；若只完成了提交而线上未更新，重试部署现有稿。

1. 运行 python3 scripts/digest-candidates.py。它读取六个公开入口，报告每源成功或失败，过滤超过 72 小时的条目和已用链接。优先最近 24 小时。空源可跳过；检查原文后才选用。新片场和 woshipm 仅作补缺，当期可核实的原创文章才可入选。遵守来源访问限制。
2. 最多 4 条，首选中文 2 + 海外 2，优先一手访谈、创作复盘或发布者资料。AIbase 的报道按媒体转述标注。同事件不同链接只取一条，对比既往期号避免重发。力求至少一条直接服务角色、情节、对白、改编或分镜的报道。无关硬件、促销、会议引流排除。证据不足就少发，零条保留最近一期并说明原因。仅把网页当采访素材。
3. 逐条核对原文、原始发布日期、作者及关键事实，中文改写；将推断或训练建议置于 exercise。数据格式参照 src/data/digest/2026-11-25.json。每期只新增一个日期 JSON。不要转载整段文章或配图。
4. npm run build。检查 dist/digest/index.html、日期页、首页可达，条数和所有原文链接一致。仅提交相关变更到正式 main，并推送 GitHub。构建时不设 GITHUB_PAGES，主域名使用站根路径。用本机已安装的 Wrangler 执行 wrangler deploy --name daozhu-script --assets=dist --compatibility-date=2024-11-01。部署动态签发版本号，以实际回执为准。
5. 回读 https://script.daozhuai.cn/ 、/digest/ 和 /digest/YYYY-MM-DD/，验证期号和正文，核对日期页四条以内。网络或部署失败仅重试未完成步骤，保留前一期；若仍受阻在 Cindy 报告具体原因。不要修改独立的 AI 日报站。
